# 現行 Swift 版との差分

原本の各 ID から現行コードと受入条件を引ける。[NAV](NAV.tsv) · [CHAT](CHAT.tsv) · [DEV](DEV.tsv) · [CFG](CFG.tsv) · [HOST](HOST.tsv) · [RPC](RPC.tsv) · [UI](UI.tsv)。[61画面の対応表](screens.tsv) には、対応先のない画面も含む。

操作・設定・分岐1,494行の内訳は、同等候補43、部分対応144、未対応1,205、構成差80、未判定17、対象外5。同等候補はソース比較の判定。配布版の GUI で実行した範囲は [検証結果](../results/README.md) に記載した。

| 機能 ID | 原本と現行 Swift の差 | 受入時の観測 |
|---|---|---|
| CHAT-058、DEV-001、NAV-232 | 原本は追加方法のパレットから Local folder を選ぶ。Swift はパス入力と Browse のシートを持つ。 | 登録先・下書き・フォーカスを照合。Browse の OS シートでの選択確定と登録は追加検証が必要。 |
| CHAT-001、088、089 | 原本は再起動時に最近のプロジェクトの下書きへ、Swift は以前の会話へ移った。 | 起動直後の画面と、履歴を含めて続けられることを別に検査。 |
| CHAT-160、162 | 原本の Supervised は要求単位で止まり、拒否・承認を選べる。Swift ではプロジェクト単位の Shell and edits がある。 | 許可前の副作用と、回答が一度だけ返ることを検査。 |
| DEV-023、024 | 原本では worktree の準備失敗がスレッドに残る。Swift は失敗時に下書きを保持して再送できる。 | 処理中・失敗・Retry 時の ID、作業先、送信文を追跡。 |
| DEV-049、057、156 | 原本は選択したファイルだけをコミットできる。Swift は Git のインデックスをコミットする。 | HEAD の内容、選外の編集、ステージ状態、端末の cwd を照合。 |

Swift では独立した新規ストア、Pi SDK、Keychain を用いる。各ドライバー固有の画面、リモート接続、外部 OAuth アカウント管理は、既に対応済みと数えない。既定オフに決まったテレメトリの方針と、機能選択の基準は [実装引き継ぎ](../../README.md) に記載した。
